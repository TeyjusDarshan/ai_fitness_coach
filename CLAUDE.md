# AI Fitness Coach

## Database Schema (Supabase)

Project: `khwrrvmejvrupokvfwvf` ("AI powered Fitness trainer", region `ap-northeast-1`, Postgres 17.6).

> ⚠️ **RLS is disabled on every table below.** All 6 tables are exposed to the `anon`/`authenticated` roles — anyone with the publishable key can read or write every row. This is only tolerable while the data is public reference content (exercise library); revisit before adding user-specific data. Remediation SQL is available on request — don't apply it blind, since enabling RLS with no policies blocks all access.

> The schema is sourced from `utilities/workout_builder/data/exercises.csv` and `relationships.csv`. Tables are created but **not yet populated** — see those CSVs for the data to migrate.

### Entity overview

`exercises` is the hub table. `movement_types`, `equipment`, and `joints` are lookup tables. `exercise_loaded_joints` is a many-to-many join between `exercises` and `joints`. `exercise_relationships` is a self-referential edge table (progression/regression links between exercises).

```
movement_types ─┐
                ├─< exercises >─┬─< exercise_loaded_joints >─ joints
equipment ──────┘               └─< exercise_relationships >─ exercises (self-referential: from/to)
```

### Lookup tables

| Table | Columns | Notes |
|---|---|---|
| `movement_types` | `id` PK, `name` unique | squat, push, pull, hinge, lunge, carry, rotation |
| `equipment` | `id` PK, `name` unique | bodyweight, resistance bands |
| `joints` | `id` PK, `name` unique | ankle, knee, hip, spine, shoulder, elbow, wrist |

### `exercises` — hub table

Maps to `exercises.csv`. The CSV's `loaded_joints` (semicolon-delimited) is normalized into `exercise_loaded_joints`.

| Column | Type | Notes |
|---|---|---|
| `id` | int4 PK | `GENERATED BY DEFAULT AS IDENTITY` — CSV IDs can be inserted explicitly |
| `name` | varchar | |
| `movement_type_id` | int4, nullable, FK → `movement_types.id` | no cascade |
| `orientation` | varchar, nullable | check ∈ `horizontal, vertical` (NULL where CSV blank) |
| `dominant` | bool, nullable | |
| `equipment_id` | int4, nullable, FK → `equipment.id` | single-valued per exercise; no cascade |
| `min_reps` / `max_reps` | int2, nullable | rep range |
| `avoid_if` | text, nullable | contraindications |
| `on_board` | bool, default `true` | |
| `board_x` / `board_y` | float8, nullable | board coordinates |
| `created_at` | timestamptz, default `now()` | |

### `exercise_loaded_joints` — many-to-many join

Composite PK. Populated from the semicolon-delimited `loaded_joints` column in `exercises.csv`.

| Column | Type | Notes |
|---|---|---|
| `exercise_id` | int4, FK → `exercises.id` | `ON DELETE CASCADE` |
| `joint_id` | int4, FK → `joints.id` | no cascade |

PK: (`exercise_id`, `joint_id`).

### `exercise_relationships` — self-referential edges

Maps to `relationships.csv`. Each row links a `from` exercise to a `to` exercise with a direction.

| Column | Type | Notes |
|---|---|---|
| `id` | int4 PK | `GENERATED BY DEFAULT AS IDENTITY` |
| `from_exercise_id` | int4, FK → `exercises.id` | `ON DELETE CASCADE` |
| `to_exercise_id` | int4, FK → `exercises.id` | `ON DELETE CASCADE` |
| `type` | varchar | check ∈ `progression, regression` |
| `reason` | text, nullable | e.g. "Lack of strength", "RIR > 3 and hit rep ceiling" |

Unique: (`from_exercise_id`, `to_exercise_id`, `type`).

### Notes on FK delete behavior

`movement_type_id` and `equipment_id` on `exercises` have no cascade, so deleting a lookup row is blocked while referenced. The join/edge tables (`exercise_loaded_joints`, `exercise_relationships`) cascade on delete from `exercises`. Indexes exist on all FK columns.
